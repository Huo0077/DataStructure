## 8.1 自平衡二叉搜索树的设计哲学与演进脉络

在上一章中我们看到，基础 BST 在最坏情况下会彻底退化为 \(O(n)\) 的链表。为了驯服这种倾斜，计算机科学家们走过了三条不同的演进路径：

```text
                                  【自平衡二叉搜索树演进】
                                             │
             ┌───────────────────────────────┼──────────────────────────────┐
             ▼                               ▼                              ▼
    【严格高度平衡：AVL 树】        【适度平衡：红黑树】          【自适应局部性：伸展树】
    - 发明于 1962 年 (苏联数学家)   - 发明于 1972 年 (Bayer)       - 发明于 1985 年 (Tarjan & Sleator)
    - 追求绝对对称 (|BF| <= 1)      - 追求黑高平衡 (最长 <= 2*最短) - 放弃显式平衡条件
    - 树极矮，查找性能登峰造极      - 插入删除至多 3 次旋转        - 每次访问将节点 Splay 至根
    - 频繁插入删除时旋转成本偏高    - 工业界事实标准 (STL / Linux)  - 空间 0 额外开销，均摊 O(log n)
```

<a id="c08-8-2"></a>
## 8.2 AVL 树：严格高度平衡的开山之作

<a id="c08-8-2-1"></a>
### 8.2.1 平衡因子（BF）与最少节点数推导（斐波那契序列）

**定义**：节点 \(x\) 的**平衡因子（Balance Factor, BF）** 为其左子树高度减去右子树高度：
\[
\text{BF}(x) = \text{height}(x.\text{left}) - \text{height}(x.\text{right})
\]
**AVL 不变量**：树中**每一个节点**的平衡因子必须满足：\(\text{BF}(x) \in \{-1, 0, 1\}\)。一旦任何节点的 \(|\text{BF}| > 1\)，立即触发旋转修复。

#### AVL 树的高度上界推导：
设高度为 \(h\) 的 AVL 树所需要的最少节点数为 \(N(h)\)：
- \(N(0) = 1\)（只有根节点）；
- \(N(1) = 2\)；
- 要让高度为 \(h\) 且节点最少，其左右子树高度必须分别为 \(h-1\) 和 \(h-2\)：
\[
N(h) = N(h - 1) + N(h - 2) + 1
\]
这与**斐波那契数列（Fibonacci Sequence）**高度同构！根据斐波那契数列的通项公式（黄金分割比 \(\phi = \frac{1 + \sqrt{5}}{2} \approx 1.618\)）：
\[
N(h) \approx \frac{\phi^{h+2}}{\sqrt{5}} - 1 \implies h < 1.44 \log_2(n + 2) - 0.328
\]
**结论**：即使在最坏情况下，AVL 树的高度也绝对不超过 \(1.44 \log_2 n\)。查找性能极度稳定。

<a id="c08-8-2-2"></a>
### 8.2.2 四大失衡形态与旋转原理（纯 ASCII 规范图解）

当在 AVL 树中插入一个新节点导致某个祖先节点失衡（\(|\text{BF}| = 2\)）时，根据插入位置与失衡节点的关系，分为四种情况：

#### 1. LL 型失衡（在左孩子的左子树插入） $\implies$ 执行【右单旋】
```text
        y (BF = 2)                        x (BF = 0)
       / \                               / \
      x   T3           右单旋           T1   y
     / \             ─────────>             / \
    T1  T2                                 T2  T3
   /
 [新增]

指针变更核心:
  1. x = y->left;
  2. y->left = x->right; (T2 过继给 y)
  3. x->right = y;
  4. 先更新 y 的高度，再更新 x 的高度！
```

#### 2. RR 型失衡（在右孩子的右子树插入） $\implies$ 执行【左单旋】（与 LL 完全镜像）
```text
      y (BF = -2)                         x (BF = 0)
     / \                                 / \
    T1  x              左单旋           y   T3
       / \           ─────────>        / \
      T2  T3                          T1  T2
           \
          [新增]
```

#### 3. LR 型失衡（在左孩子的右子树插入） $\implies$ 先对左子【左旋】，再对根【右旋】
```text
       y (BF = 2)                   y (BF = 2)                     z (BF = 0)
      / \                          / \                            / \
     x   T4       对 x 左单旋     z   T4       对 y 右单旋       x   y
    / \          ───────────>    / \          ───────────>      / \ / \
   T1  z                        x  T3                          T1 T2T3 T4
      / \                      / \
     T2  T3                   T1  T2
```

#### 4. RL 型失衡（在右孩子的左子树插入） $\implies$ 先对右子【右旋】，再对根【左旋】（与 LR 完全镜像）

> ⚠️ **更新高度的依赖原则**：  
> 旋转完成后，节点的位置发生了高低颠倒。**必须先重新计算下层节点（原根节点 \(y\)）的高度，再计算上层新根节点（\(x\) 或 \(z\)）的高度**！颠倒次序将导致祖先节点读到过期的脏高度！

<a id="c08-8-2-3"></a>
### 8.2.3 插入与删除的旋转代价差异剖析

- **插入操作**：插入一个节点后，沿着回溯路径向上检查。**至多需要 1 次单旋或 1 次双旋（共 1~2 次局部旋转），子树高度就会恢复为插入前的高度**，失衡不会继续向上传播，旋转立即终止！
- **删除操作**：删除一个节点并旋转修复后，该子树的高度可能会比删除前降低 1。这一高度变化可能导致其父节点乃至更高层的祖先**再度失衡**！因此，在最坏情况下，删除操作可能需要沿着整条到达根节点的路径进行 \(O(\log n)\) 次连续旋转。

## 8.3 红黑树（Red-Black Tree）：工业界首选的工程艺术

红黑树是自平衡 BST 领域的工程霸主。从 C++ STL 的 `std::map`、`std::set`，到 Linux CFS 完全公平调度器，再到 Java 的 `TreeMap` 和 epoll 事件就绪队列，背后全都是红黑树的身影。

<a id="c08-8-3-1"></a>
### 8.3.1 五大红黑性质的数学本质与黑高（Black-Height）定理

红黑树是一棵在每个节点上增加了一个存储位表示节点颜色（`RED` 或 `BLACK`）的二叉搜索树。它必须严格满足以下五条性质：

1. **每个节点要么是红色的，要么是黑色的**；
2. **根节点永远是黑色的**；
3. **所有的叶子节点（NIL 哨兵节点）被视为黑色**；
4. **如果一个节点是红色的，则它的两个子节点必须全都是黑色的**（即：绝对不允许出现连续两个红色节点）；
5. **从任意节点出发到其所有后代叶子节点的每条简单路径上，均包含相同数目的黑色节点**（这条性质被称为“**黑高相同**”）。

```text
                     [8, B] (bh=2)
                    /      \
             [4, R]          [12, R]
            /      \        /       \
        [2, B]    [6, B] [10, B]   [14, B]
        /    \    /    \  /    \   /     \
       NIL  NIL  NIL  NIL NIL NIL NIL   NIL  (全部 NIL 均为黑色，黑高均为 2)
```

#### 为什么这五条性质能保证树的高度对数受限？
- 根据性质 5，每条路径上的黑色节点数目必须完全相等（设为 \(bh\)）；
- 根据性质 4，红色节点不能相邻，这意味着：在任意路径中，红色节点的数量至多等于黑色节点的数量；
- 因此：
  - **最短可能路径**：全黑节点，长度为 \(bh\)；
  - **最长可能路径**：红黑交替相间，长度为 \(2 \cdot bh\)；
- **核心推论**：一棵包含 \(n\) 个内部节点的红黑树，其高度至多为 \(2 \log_2(n + 1)\)！

> **深层不变量直观**：  
> 黑色节点才是红黑树的“真正主干”，而红色节点只是“寄居”在黑色节点周围、用于吸收动态变化的缓冲垫！

<a id="c08-8-3-2"></a>
### 8.3.2 红黑树与 2-3-4 树的完美同构投影（顿悟之钥）

许多人觉得红黑树的变色和旋转极其神秘。其实，**红黑树在本质上就是经典 B 树家族中 2-3-4 树的“二叉形式等价物”**！

```text
【2-3-4 树中的 3-节点】            【等价的红黑树子结构 (红色节点向黑色父节点贴靠)】
       [ B | C ]                            C (黑)               B (黑)
       /   │   \                           /   \        或      /   \
      T1   T2   T3                        B(红) T3             T1    C(红)
                                         / \                        / \
                                        T1  T2                     T2  T3

【2-3-4 树中的 4-节点】            【等价的红黑树子结构 (两红夹一黑)】
     [ B | C | D ]                          C (黑)
     /   │   │   \                         /   \
    T1  T2  T3   T4                       B(红) D(红)
                                         / \   / \
                                        T1 T2 T3 T4
```

- **红黑树的变色** $\iff$ 2-3-4 树中 4-节点满载时的**裂变（Split）**；
- **红黑树的旋转** $\iff$ 2-3-4 树中节点内部子树形态的**重平衡（Rebalance）**！  
只要脑海中有这幅同构图，红黑树的全部修复逻辑将瞬间洞若观火！

<a id="c08-8-3-3"></a>
### 8.3.3 插入修复的三大场景与变色旋转演进

**插入准则**：新插入的节点 \(z\) 默认染成**红色**。  
*为什么是红色？* 因为插入红色节点绝不会破坏性质 5（黑高平衡），它唯一可能破坏的是性质 2（若为根）或性质 4（若父节点恰好也是红色，产生“红红冲突”）。

设新节点为 \(z\)，父节点为 \(p\)，祖父节点为 \(g\)，叔叔节点为 \(u\)（设 \(p\) 为 \(g\) 的左孩子，右侧对称）：

#### 【Case 1】叔叔节点 \(u\) 是红色 $\implies$ 变色并向上传递
```text
           g (黑)                                 g (红)  <=== 问题转移到 g，继续向上循环
          /      \                               /      \
       p (红)    u (红)         变色            p (黑)   u (黑)
       /                       ──────>         /
     z (红)                                  z (红)
```
**操作**：令 \(p\) 和 \(u\) 染为黑色，\(g\) 染为红色；将当前考察节点指针移到 \(g\)，继续向上检查。

#### 【Case 2】叔叔节点 \(u\) 是黑色，且 \(z\) 是右孩子（折线型） $\implies$ 对 \(p\) 左旋转化为 Case 3
```text
           g (黑)                                 g (黑)
          /      \         对 p 左旋             /      \
       p (红)    u (黑)   ─────────>          z (红)    u (黑)
         \                                    /
         z (红)                             p (红)
```
**操作**：令当前节点 \(z = p\)，对 \(p\) 执行左单旋，形态瞬间转化为直线型（Case 3）。

#### 【Case 3】叔叔节点 \(u\) 是黑色，且 \(z\) 是左孩子（直线型） $\implies$ 变色 + 对 \(g\) 右旋（终结！）
```text
           g (黑)                                 p (黑)
          /      \        p 染黑, g 染红         /      \
       p (红)    u (黑)   ────────────>        z (红)   g (红)
       /                   对 g 右旋                    /      \
     z (红)                                           T2      u (黑)
```
**操作**：令 \(p\) 染黑，\(g\) 染红，对 \(g\) 执行右单旋。**红红冲突彻底化解，全树恢复平衡，直接终止！**

<a id="c08-8-3-4"></a>
### 8.3.4 删除修复的四大分支彻底剖析（“双重黑色”与借黑还红）

删除是红黑树中最艰深的部分。
- 若删除的是红色节点，黑高未变，无需任何修复；
- 若删除（或移走）的是**黑色节点**，经过该路径的黑色节点数减少了 1，性质 5 被破坏！
- **核心抽象**：设取代被删位置的节点为 \(x\)，我们认为 \(x\) 额外背负了一层黑色，即成为**双重黑色（Double-Black）**节点。删除修复的使命，就是**将这个多余的黑色推向根部消解，或者通过兄弟节点借调黑色来消除**！

设 \(x\) 是其父节点 \(p\) 的左孩子，兄弟节点为 \(w\)：

#### 【Case 1】兄弟节点 \(w\) 是红色
```text
         p (黑)                                 w (黑)
        /      \          p 染红, w 染黑       /      \
     x (双黑)   w (红)    ────────────>      p (红)   w->right (黑)
               /     \     对 p 左单旋       /     \
            w->left  w->right             x (双黑) w->left
```
**本质**：通过旋转和变色，将红兄弟转化为黑兄弟，从而顺利套用后续的 Case 2/3/4！

#### 【Case 2】兄弟 \(w\) 是黑色，且 \(w\) 的两个孩子全为黑色
```text
         p (颜色任意)                            p (吸收一层黑)
        /          \          w 染红            /             \
     x (双黑)       w (黑)   ────────>        x (恢复单黑)    w (红)
                   /     \                                  /     \
                 黑       黑                               黑       黑
```
**本质**：兄弟 \(w\) 也很穷，拿不出多余的黑色。于是 \(w\) 变红（让右侧也少一个黑），将两边共同缺失的黑色上推给父节点 \(p\)。若 \(p\) 原本为红，直接染黑即可终止；若 \(p\) 为黑，则 \(p\) 成为新的双黑节点向上回溯。

#### 【Case 3】兄弟 \(w\) 为黑色，近侧侄子（左孩子）为红，远侧侄子（右孩子）为黑
```text
         p (颜色任意)                            p (颜色任意)
        /          \         近侄染黑, w 染红   /          \
     x (双黑)       w (黑)   ──────────────>  x (双黑)    w->left (黑)
                   /     \     对 w 右旋                     \
                红(近侄)  黑(远侄)                           w (红)
                                                               \
                                                                黑
```
**本质**：近侧红侄子无法在左旋后支撑黑高，先通过右单旋将红色“转运”到远侧，转换为 Case 4。

#### 【Case 4】兄弟 \(w\) 为黑色，远侧侄子（右孩子）为红色（绝杀！）
```text
         p (颜色 C)                              w (继承颜色 C)
        /          \         w 继承 p 颜色      /             \
     x (双黑)       w (黑)   p 与 远侄 染黑    p (黑)          远侄 (黑)
                   /     \   ─────────────>   /     \
                 任意     红(远侄) 对 p 左旋 x (单黑) 任意
```
**本质**：远侧侄子富得流油！通过一次对 \(p\) 的左旋，把兄弟 \(w\) 提到父节点位置，让它继承 \(p\) 的颜色；同时将 \(p\) 和远侄染黑。此时左侧双黑被彻底化解，右侧黑高完全平衡，**算法完美终止！**

## 8.4 伸展树（Splay Tree）：自适应访问与均摊分析典范

<a id="c08-8-4-1"></a>
### 8.4.1 核心哲学：局部性原理与“访问即重构”

在实际计算中，**数据的访问极不均衡**——80% 的查询往往集中在 20% 的热点数据上（80/20 法则与时间局部性）。  
由图灵奖得主 Robert Tarjan 和 Daniel Sleator 发明的**伸展树（Splay Tree）** 贯彻了极简主义：
- 节点中**不存储任何平衡因子或颜色标记**；
- 每次访问（查找、插入、删除）任何一个节点 \(x\) 后，立即执行一系列旋转，**将节点 \(x\) 强行旋转到树根（Splay 操作）**；
- 从而让刚刚访问过的热点数据在接下来的访问中只需 \(O(1)\) 即可直接命中！

<a id="c08-8-4-2"></a>
### 8.4.2 三种 Splay 旋转：为什么 Zig-Zig 必须先旋父再旋子？

#### 1. Zig 操作（单旋）：当父节点 \(p\) 已经是根节点时，单旋一次直接到根。
#### 2. Zig-Zag 操作（双旋，异侧）：\(x\) 与 \(p\) 处于异侧折线，与 AVL 的 LR/RL 类似，连续旋转 \(x\) 两次。
#### 3. Zig-Zig 操作（双旋，同侧）：\(x\) 与 \(p\) 处于同一直线。

```text
【致命关键：Zig-Zig 必须“先旋父节点 p，再旋自身 x”！】
          g                      p                      x
         / \                    / \                    / \
        p   D      先绕 g 旋 p  x   g      再绕 p 旋 x    A   p
       / \       ───────────>  / \ / \   ───────────>        / \
      x   C                   A  B C  D                     B   g
     / \                                                       / \
    A   B                                                     C   D
```

> **为什么不能先旋 x 再旋 x？**  
> 如果像朴素单旋那样连续对 \(x\) 旋转两次，整棵子树的结构只是被粗暴地拉扯，原先很深的树高依然很深！  
> 而**先旋父再旋子**能够将从 \(g\) 到 \(x\) 的整条瘦长路径**沿途折叠对半砍（Halving Effect）**！正是这种折叠效应，才在数学上严格保证了 Tarjan 的势能函数分析成立，从而赋予了伸展树令人惊叹的**均摊 \(O(\log n)\)** 复杂度！

## 8.5 平衡树家族横向技术选型雷达

| 维度 | AVL 树 | 红黑树 | 伸展树 (Splay) |
| :--- | :--- | :--- | :--- |
| **平衡度** | 极严格（高度差 \(\le 1\)） | 适度（最长 \(\le 2 \times\) 最短） | 动态自适应（无显式平衡界） |
| **最大树高** | \(\approx 1.44 \log_2 n\) | \(\le 2 \log_2(n + 1)\) | 最坏单次 \(O(n)\)，均摊 \(O(\log n)\) |
| **额外空间开销** | 每个节点存一个 `int height` | 每个节点存 1 个 bit（`Color`） | **0 额外空间**（纯粹的指针） |
| **插入旋转次数** | 至多 2 次旋转 | 至多 2 次旋转，若干次变色 | 伴随路径重构 |
| **删除旋转次数** | 最坏需 \(O(\log n)\) 次 | **至多 3 次旋转！** | 伴随路径重构 |
| **最适合场景** | **读多写极少**（如静态只读字典） | **读写均衡的高频增删**（如 STL map） | **局部性极强、热点集中**（如缓存代理） |

<a id="c08-summary"></a>
## 本章小结

1. **AVL 是严谨的数学对称之美**：以严格的高度差换取了极致的查询速度，插入只需常数次旋转，但删除可能沿途多次调整。
2. **红黑树是工业妥协的最高境界**：通过引入红色的缓冲机制，将插入和删除的旋转次数全部压制在常数步（\(\le 3\) 次），是写密集型业务的不二之选。
3. **2-3-4 树是红黑树的解密钥匙**：变色即分裂，旋转即重排，看透这一点便不再畏惧红黑树代码。
4. **伸展树的折叠智慧**：放弃静态规则，拥抱时间局部性；Zig-Zig 先父后子的旋转次序是均摊对数复杂度的数学灵魂。

## 思考题与经典大厂面试题

1. **为什么红黑树删除最多只需 3 次旋转？**：对照 Case 1~4 的状态转移图，证明从任何一个失衡状态开始，在执行至多 3 次旋转后必定进入终止状态。
2. **左倾红黑树（LLRB, Left-Leaning Red-Black Tree）**：Robert Sedgewick 提出的 LLRB 规定“所有红色链接必须向左倾斜”。相比标准红黑树，这种约束如何简化了插入和删除的代码实现？
3. **Splay 树的势能证明简述**：设节点 \(x\) 的秩 \(r(x) = \lfloor \log_2(\text{size}(x)) \rfloor\)，整棵树的势能 \(\Phi = \sum r(x)\)。试简述为什么先旋父后子的 Zig-Zig 操作能够产生负的势能变化量。
