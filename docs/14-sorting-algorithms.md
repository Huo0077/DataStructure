## 14.1 排序问题的理论基石：稳定性与决策树下界证明

<a id="c14-14-1-1"></a>
### 14.1.1 稳定性的工程价值（多关键字排序）

**稳定性定义**：若待排序序列中存在两个相等的关键字 \(K_i = K_j\)，且在排序前 \(K_i\) 领先于 \(K_j\)；若排序后 \(K_i\) **依然严格领先于** \(K_j\)，则称该算法是**稳定的（Stable）**。

```text
原始学生成绩表 (已预先按学号 1, 2, 3 升序排列):
[ (张三, 90分, 学号1),  (李四, 90分, 学号2),  (王五, 80分, 学号3) ]

【若使用稳定排序按分数降序】:
[ (张三, 90分, 学号1),  (李四, 90分, 学号2),  (王五, 80分, 学号3) ]
（同分的张三依然排在李四前面，保持了先前的学号顺序！）

【若使用不稳定排序 (如快排/堆排)】:
[ (李四, 90分, 学号2),  (张三, 90分, 学号1),  (王五, 80分, 学号3) ]
（学号顺序被强行打乱，之前排序的成果前功尽弃！）
```

<a id="c14-14-1-2"></a>
### 14.1.2 比较排序下界的决策树严格数学证明（Stirling 公式）

在**基于比较的排序模型（Comparison Sort）**中，算法只能通过两两比对元素（\(a_i \le a_j\)）来决定相对次序。

```text
决策树模型 (对包含 3 个元素的数组 [a, b, c] 进行比较):
                     [ a : b ]
                    /         \
                 <=             >
             [ b : c ]       [ a : c ]
            /         \     /         \
         <=             > <=            >
       a<=b<=c        ... ...         c<b<a  (叶子节点 = 某种置换)
```

#### 证明过程：
1. \(n\) 个互异元素共有 \(n!\) 种不同的排列置换；
2. 排序算法必须能够区分出这 \(n!\) 种可能，这意味着决策树的**叶子节点总数 \(L \ge n!\)**；
3. 一棵高度为 \(h\) 的二叉树，其叶子节点最多为 \(2^h\) 个。因此必有：
\[
2^h \ge L \ge n! \implies h \ge \log_2(n!)
\]
4. 根据**斯特林公式（Stirling's Approximation）**：
\[
n! \approx \sqrt{2\pi n} \left( \frac{n}{e} \right)^n
\]
\[
\log_2(n!) = \sum_{i=1}^n \log_2 i \ge \sum_{i=\lceil n/2 \rceil}^n \log_2 \left(\frac{n}{2}\right) = \frac{n}{2} \log_2 \left(\frac{n}{2}\right) = \Omega(n \log_2 n)
\]
**结论**：在最坏情况下，**任何基于比较的排序算法至少需要执行 \(\lceil \log_2(n!) \rceil \approx \Omega(n \log n)\) 次比较**！任何号称“比较排序做到 \(O(n)\)”的说法在数学上都是荒谬的。

## 14.2 O(n²) 基础排序的优雅与局限

<a id="c14-14-2-1"></a>
### 14.2.1 插入排序：小数据量与近乎有序数据的无敌王者

模拟摸牌理牌的过程：已排序区间在左，未排序区间在右。每次取一张新牌，在左侧已排序区间中从右向左扫描并后移大于它的牌，找到合适位置插入。

- **最好情况（完全有序）**：每张牌只需比对 1 次，总时间 \(O(n)\)；
- **小数据性能极速**：当 \(n \le 32 \sim 64\) 时，由于无递归开销且完全是连续内存比较，其常数因子比快排小得多！现代高性能混合排序（如 `std::sort` 的 Introsort 和 TimSort）**在底层均无一例外地退回使用插入排序**。

<a id="c14-14-2-2"></a>
### 14.2.2 希尔排序（Shell Sort）：打破平方屏障的步长跃迁

1959 年 Donald Shell 提出了第一个突破 \(O(n^2)\) 的排序算法。  
**核心思想**：通过步长序列（Gap）将数组分组，对每组分别执行插入排序。步长逐渐缩小，最终 `gap = 1` 时数组已高度有序，插入排序近乎以 \(O(n)\) 极速收尾。
- **Hibbard 增量序列**（\(2^k - 1\)）：最坏时间复杂度为 \(O(n^{1.5})\)；
- **Sedgewick 增量序列**：最坏时间复杂度可优化至 \(O(n^{4/3}) \approx O(n^{1.33})\)。

<a id="c14-14-3"></a>
## 14.3 O(n log n) 三大巨头的分治与堆化

<a id="c14-14-3-1"></a>
### 14.3.1 归并排序（Merge Sort）与逆序对统计

- **分治法（Divide and Conquer）**：将数组一分为二，递归排序左右两半，再通过两个指针以 \(O(n)\) 线性合并；
- **严格稳定**：合并时只要左半部分元素 \(\le\) 右半部分元素，优先放入左侧元素；
- **空间代价**：合并时需要 \(O(n)\) 的辅助数组；
- **逆序对统计应用**：当右侧指针元素 \(arr[j]\) 被优先取走时，说明左侧区间内从当前位置到中点的所有剩余元素（共 \(mid - i + 1\) 个）均大于 \(arr[j]\)，借此可在线性对数时间内统计出数组中的逆序对总量。

<a id="c14-14-3-2"></a>
### 14.3.2 快速排序（Quick Sort）：三大划分方法深度剖析

由 Tony Hoare 于 1959 年发明。其平均性能是同级别比较排序中常数因子最小的，被誉为 20 世纪最伟大的算法之一。

#### 1. Lomuto 划分（单向推进，逻辑直观）
选取末尾元素为 Pivot，维护指针 \(i\)。所有比 Pivot 小的元素被连续排在 \([0, i]\)，指针 \(j\) 向前探路：
```text
[ 小于 Pivot 区域 (0..i) ] [ 大于等于区域 (i+1..j-1) ] [ 未知探索区 (j..n-2) ] [ Pivot ]
```

#### 2. Hoare 划分（双向对撞，极其高效）
左右双指针同时向中间扫描。左指针寻找大于等于 Pivot 的元素，右指针寻找小于等于 Pivot 的元素，两者发生逆序则交换并继续推进。交换次数远少于 Lomuto。

#### 3. 三向切分（3-Way Partition / 荷兰国旗问题）
面对包含**海量重复元素**的数组（如只有 0 和 1），普通快排会因为无法均分元素而退化为 \(O(n^2)\)！三向切分将数组严格划分为三部分：
```text
┌────────────────┬────────────────┬────────────────┬────────────────┐
│   < Pivot 区域  │   == Pivot 区域 │   未处理区域    │   > Pivot 区域  │
└────────────────┴────────────────┴────────────────┴────────────────┘
```
只需对 `< Pivot` 和 `> Pivot` 的两侧递归，相等区间直接跳过，排序速度接近线性 \(O(n)\)！

<a id="c14-14-3-3"></a>
### 14.3.3 堆排序（Heap Sort）：极致的 O(1) 空间权衡

先用 \(O(n)\) 建大顶堆，再将堆顶与末尾交换并下沉，原地完成排序。不占用额外空间，但由于在数组中跨步下沉寻址，**CPU 缓存局部性较差**，实际常数慢于快排。

## 14.4 工业级混合排序之王：TimSort 深度解密

2002 年 Tim Peters 为 Python 语言设计了 TimSort，随后被 Java SE 7、Android 和 Chrome V8 引擎采纳为标准排序器。

<a id="c14-14-4-1"></a>
### 14.4.1 真实世界数据的 Run 模式与 minrun 选择

真实世界的数据极少是完全纯随机的，往往包含大量的“局部连续单调递增”或“局部单调递减”的片段，称为 **Run**。
- **识别 Run**：扫描输入数据，若发现连续递增，扩展该 Run；若发现连续严格递减，就地将其翻转为递增；
- **minrun 哲学**：为了保证归并平衡，TimSort 规定每个 Run 的长度至少为 `minrun`（通常在 32 到 64 之间）。若识别出的自然 Run 长度不足 `minrun`，**使用二分插入排序（Binary Insertion Sort）强行补齐**！

<a id="c14-14-4-2"></a>
### 14.4.2 栈式归并约束与飞奔模式（Galloping Mode）

- **归并栈不变量**：维护一个存放已就绪 Run 的栈，栈顶三个 Run 的长度 \(A, B, C\) 必须时刻满足：
  1. \(A > B + C\)
  2. \(B > C\)  
  这保证了归并过程高度贴合斐波那契数列，使得归并层数严格控制在 \(O(\log n)\)！
- **飞奔模式（Galloping Mode）**：当归并两个 Run 时，若发现连续多次都是其中一个 Run 的元素胜出（阈值通常为 7 次），算法认为该 Run 存在大块优势区间，立即切换为**指数步长搜索（1, 2, 4, 8...）配合二分查找**，一次性批量拷贝整片数据，大幅削减比较次数！

## 14.5 超越比较下界：非比较排序的数论哲学

非比较排序不进行元素间的大小比对，而是利用键的数字特征，实现 \(O(n)\) 级别的突破。

<a id="c14-14-5-1"></a>
### 14.5.1 计数排序：前缀累加和的稳定定位法

当待排元素均为 \([0, k]\) 内的整数且 \(k = O(n)\) 时：
1. 统计每个元素出现的频次 `count[val]`；
2. **核心技巧：计算前缀和**！`count[i] = count[i] + count[i-1]`。此时 `count[val]` 的值恰好表示“小于等于 `val` 的元素总个数”，即该元素在输出数组中的**最终下标上限**；
3. **逆序扫描原数组**：将元素放入对应位置并递减 `count`，完美保证稳定性！

<a id="c14-14-5-2"></a>
### 14.5.2 基数排序：为什么 LSD 必须从低位到高位？

**最低位优先（LSD, Least Significant Digit first）**：
- 依次按个位、十位、百位进行稳定的计数排序；
- **为什么必须从低位到高位？**  
  因为高位对大小起决定性支配作用！根据稳定性定理，在完成了第 \(k\) 位的排序后，若两数第 \(k\) 位相同，它们在第 \(k-1\) 位形成的相对顺序将被稳定保持下来！

## 14.6 海量数据与外存挑战：外部排序与败者树（Loser Tree）

当数据量高达 1TB，而物理内存仅有 1GB 时，内排序无法一次性载入全部数据。

<a id="c14-14-6-1"></a>
### 14.6.1 K 路平衡归并的两阶段流程

1. **阶段一：生成初始归并段（Runs）**  
   分批次将 1GB 数据读入内存，用快排排好序后写回磁盘，生成 \(M\) 个初始有序段；
2. **阶段二：K 路多路归并**  
   同时打开 \(K\) 个有序段文件的输入流，每次从这 \(K\) 个流中选出最小者输出到最终文件。

<a id="c14-14-6-2"></a>
### 14.6.2 败者树原理：为什么比较次数比堆减少一半？

在 \(K\) 路归并中，若使用常规二叉堆选最小：
- 堆顶弹出后，推入一个新元素，该元素需要与左右两个孩子各比较一次，在每层需要 2 次比较，总比较次数为 \(2 \log_2 K\)。

```text
败者树结构: 内部节点记录的是【败者（输者）的归并段编号】，胜者（赢者）继续向上比
                      [ 冠军 ]
                         │
                      [ 败者 ] (第 1 轮胜者与该败者比较)
                     /        \
                 [ 败者 ]     [ 败者 ]
```
- **败者树重赛（Replay）**：新元素进入后，沿着到根节点的单一路径向上，**每层只需与该节点上记录的旧败者进行 1 次比较**！输者留在节点中，赢者继续向上！
- **比较次数由 \(2 \log_2 K\) 减半为 \(\log_2 K\)**！在万级路数归并中，极大降低了 CPU 比较指令开销！

<a id="c14-14-6-3"></a>
### 14.6.3 置换-选择排序：生成 2M 长度初始归并段的黑魔法

普通分块只能生成长度为内存大小 \(M\) 的归并段。严蔚敏《数据结构》中经典的**置换-选择排序（Replacement Selection）**利用小顶堆：
- 只要输入的新元素比刚刚输出的元素大，就可继续纳入当前归并段；
- **数学期望推导**：平均可生成**长度高达 \(2M\) 的超长归并段**！初始段数量直接减半，外部 I/O 归并轮数减少整整一轮！

## 14.7 十大排序全维度横向雷达与选型指南

| 算法 | 平均时间 | 最坏时间 | 最好时间 | 空间复杂度 | 稳定性 | 核心工业场景 |
| :--- | :---: | :---: | :---: | :---: | :---: | :--- |
| **插入排序** | \(O(n^2)\) | \(O(n^2)\) | \(O(n)\) | \(O(1)\) | **稳定** | 小数组（\(n < 32\)）、近乎有序数据 |
| **希尔排序** | \(O(n^{1.3})\) | \(O(n^2)\) | \(O(n)\) | \(O(1)\) | 不稳定 | 嵌入式硬件、无递归栈开销场景 |
| **冒泡排序** | \(O(n^2)\) | \(O(n^2)\) | \(O(n)\) | \(O(1)\) | **稳定** | 教学演示（工业界几乎不用） |
| **选择排序** | \(O(n^2)\) | \(O(n^2)\) | \(O(n^2)\) | \(O(1)\) | 不稳定 | 极力减少写入交换次数的场景 |
| **快速排序** | \(O(n \log n)\) | \(O(n^2)\) | \(O(n \log n)\) | \(O(\log n)\) | 不稳定 | 通用内存计算、基本类型数组排序 |
| **归并排序** | \(O(n \log n)\) | \(O(n \log n)\) | \(O(n \log n)\) | \(O(n)\) | **稳定** | 链表排序、外部排序、要求稳定排序 |
| **堆排序** | \(O(n \log n)\) | \(O(n \log n)\) | \(O(n \log n)\) | \(O(1)\) | 不稳定 | 内存受限且绝对不能承受 \(O(n^2)\) 最坏情况 |
| **TimSort** | \(O(n \log n)\) | \(O(n \log n)\) | \(O(n)\) | \(O(n)\) | **稳定** | Python / Java / V8 语言级标准排序 |
| **计数排序** | \(O(n + k)\) | \(O(n + k)\) | \(O(n + k)\) | \(O(k)\) | **稳定** | 键值范围极小的离散整数排序 |
| **基数排序** | \(O(d \cdot (n + k))\) | \(O(d \cdot (n + k))\) | \(O(d \cdot (n + k))\) | \(O(n + k)\) | **稳定** | 定长数字、手机号、定长字符串 |

<a id="c14-summary"></a>
## 本章小结

1. **比较下界是数学律令**：\(\Omega(n \log n)\) 设立了不可逾越的理论鸿沟，非比较排序通过利用数字位权巧妙突围。
2. **快排的常数王者地位**：缓存局部性与划分策略让快速排序在通用内排序中独占鳌头。
3. **TimSort 敬畏现实数据**：识别自然有序的 Run 与飞奔模式，是算法理论向工程现实妥协并超越的典范。
4. **外部排序化解空间绝境**：败者树重赛减半与置换选择扩长段，彻底征服了海量磁盘数据的吞吐瓶颈。

## 思考题与经典大厂面试题

1. **三数取中法的防退化机制**：快速排序中，三数取中（Median-of-Three）是如何选定 Pivot 的？为什么它能有效抵御针对已排序数组的 \(O(n^2)\) 恶化？
2. **寻找未排序数组中的第 K 大元素（QuickSelect）**：利用快速排序的划分思想，如何以 \(O(n)\) 的平均时间复杂度（优于堆排序的 \(O(n \log k)\)）直接定位第 \(K\) 大元素？
3. **外部排序的 I/O 次数精确计算**：设待排数据有 128 个初始归并段，采用 4 路平衡归并，需要进行多少轮归并？若采用 8 路归并，I/O 次数减少多少？
