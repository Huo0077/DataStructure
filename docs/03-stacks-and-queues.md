## 3.1 操作受限的线性表：为什么需要自我设限？

初学者常常产生疑问：*“既然动态数组和双向链表可以在任意位置插入和删除，为什么还要故意阉割功能，搞出只能在端点操作的栈和队列？”*

在软件工程中，**“能力的约束”往往意味着“确定性与安全性的提升”**：
1. **防止误操作**：如果允许在调用栈中间随意插入或删除帧，整个程序的控制流将陷入不可预知的崩溃；
2. **算法表达更纯粹**：将操作限制为 `push/pop` 或 `enqueue/dequeue`，能够将问题的逻辑状态与底层复杂的内存搬移彻底隔离开来；
3. **硬件与系统友善**：CPU 内部的指令寄存器（ESP/RSP）天然以栈的形式工作，操作系统的进程调度与网络数据包缓冲天然以队列的形式流转。

## 3.2 栈 (Stack) — 后进先出 (LIFO) 原理与实现

栈（Stack）是限定仅在表的一端（栈顶，Top）进行插入和删除的线性表。另一端固定不动，称为栈底（Bottom）。

```text
                  栈顶 (Top) ───> [ 30 ]  ▲ 只能在此端 push / pop
                                  [ 20 ]  │
                  栈底 (Bottom) ─> [ 10 ]  ▼
```

<a id="c03-3-2-1"></a>
### 3.2.1 顺序栈与链式栈的实现对比

- **顺序栈（Array Stack）**：以连续数组为底层，维护 `int top` 索引（初始为 -1）。
  - `push(x)`: `data[++top] = x;`（\(O(1)\)）
  - `pop()`: `--top;`（\(O(1)\)）
  - **优势**：极度缓存友好，常数因子极小。
- **链式栈（Linked Stack）**：以单链表为底层，**链表头作为栈顶**。
  - 为什么不能以链表尾作为栈顶？因为单链表在尾部删除时需要 \(O(n)\) 寻找前驱，除非使用双向链表。

<a id="c03-3-2-2"></a>
### 3.2.2 经典应用一：括号匹配与调用栈（Call Stack）

编译器进行语法分析时，必须检查各类括号（`()`, `[]`, `{}`）是否合法嵌套。
- **核心逻辑**：遇到左括号入栈；遇到右括号，检查栈顶是否为其对应的左括号。若匹配则弹出，若不匹配或栈空则语法错误；遍历结束后栈必须为空。

<a id="c03-3-2-3"></a>
### 3.2.3 经典应用二：表达式转换（中缀转后缀）与逆波兰求值引擎

人习惯阅读中缀表达式（如 `3 + 4 * 2 / (1 - 5)`），但计算机难以直接处理括号嵌套与算符优先级。**逆波兰表达式（后缀表达式，Reverse Polish Notation, RPN）** 将操作符置于操作数之后（`3 4 2 * 1 5 - / +`），彻底消除了括号，只需一个栈即可线性求值！

#### 调度场算法（Shunting-Yard Algorithm，Dijkstra 提出）
```text
输入字符流 ───> [ 遇到数字 ] ───────────────> 直接输出到后缀队列
           ───> [ 遇到 '(' ]  ───────────────> 压入算符栈
           ───> [ 遇到 ')' ]  ───────────────> 弹出算符并输出，直到遇到 '(' (弹出并丢弃 '(')
           ───> [ 遇到运算符 op ] ───────────> 只要栈顶算符优先级 >= op，就持续弹出并输出；然后 op 入栈
```

#### 后缀表达式求值状态机（Dry-Run Trace）
计算 `"3 4 2 * 1 5 - / +"`：

| 读取符号 | 操作类型 | 栈内元素状态 | 说明 |
| :---: | :--- | :--- | :--- |
| `3` | 数字入栈 | `[3]` | |
| `4` | 数字入栈 | `[3, 4]` | |
| `2` | 数字入栈 | `[3, 4, 2]` | |
| `*` | 弹出 2, 4 计算 \(4 \times 2 = 8\) | `[3, 8]` | 先弹出的为右操作数！ |
| `1` | 数字入栈 | `[3, 8, 1]` | |
| `5` | 数字入栈 | `[3, 8, 1, 5]` | |
| `-` | 弹出 5, 1 计算 \(1 - 5 = -4\) | `[3, 8, -4]` | |
| `/` | 弹出 -4, 8 计算 \(8 / (-4) = -2\) | `[3, -2]` | |
| `+` | 弹出 -2, 3 计算 \(3 + (-2) = 1\) | `[1]` | 最终计算结果为 1 |

<a id="c03-3-2-4"></a>
### 3.2.4 变体设计：O(1) 时间的最小栈（MinStack）两种方案

设计一个栈，支持 `push`、`pop`、`top`，并能在 \(O(1)\) 时间内检索到栈中的最小元素 `getMin()`。

- **方案一：双栈同步法（经典直观）**  
  维护主栈 `dataStack` 和辅助栈 `minStack`。每次 `push(x)` 时，`minStack` 压入 `min(x, minStack.top())`。两栈高度时刻相同，空间额外占用 \(O(n)\)。
- **方案二：差值存储法（进阶空间优化）**  
  主栈不存原值，而是存入元素与当前最小值的差值：`diff = val - currentMin`。当 `diff < 0` 时，说明当前值刷新了最小值。此法在某些场景下可将空间开销压缩到极致，但需要考虑整型溢出问题。

## 3.3 队列 (Queue) — 先进先出 (FIFO) 原理与实现

队列（Queue）仅允许在表的一端插入（入队，Enqueue），在另一端删除（出队，Dequeue）。

<a id="c03-3-3-1"></a>
### 3.3.1 假溢出问题与循环队列（Circular Queue）的诞生

若使用普通顺序数组实现队列，设置 `front` 指向队首，`rear` 指向队尾。随着不断出队和入队，`front` 和 `rear` 整体向数组高端漂移：

```text
               front             rear
                 │                 │
[已出队无效区]   ▼                 ▼
┌───┬───┬───┬───┬───┬───┬───┬───┬───┐
│   │   │   │   │ A │ B │ C │ D │   │  (rear 已接近容量上限)
└───┴───┴───┴───┴───┴───┴───┴───┴───┘
```
当 `rear == capacity` 时，即使数组前端有大量空闲位置，也无法再入队新元素，这种现象称为**假溢出（False Overflow）**。

为了解决假溢出，数学上通过**取模运算（Modulo Operation）**将物理线性数组首尾相连，逻辑上视为一个环形缓冲区：
```cpp
rear = (rear + 1) % capacity;
front = (front + 1) % capacity;
```

<a id="c03-3-3-2"></a>
### 3.3.2 循环队列判空判满的三种经典设计方案

当 `front == rear` 时，队列到底是**空**还是**满**？这是数据结构考研与工业设计的核心经典命题。

```text
【方案 1：牺牲一个存储单元（最常用标准方案）】
- 队空条件: front == rear
- 队满条件: (rear + 1) % capacity == front
- 队列实际可容纳最大元素数: capacity - 1

【方案 2：维护 size 计数器】
- 结构体增加字段: size_t size = 0;
- 队空条件: size == 0
- 队满条件: size == capacity
- 空间完全利用，无需牺牲存储单元。

【方案 3：维护 tag / last_op 标记位】
- 结构体增加布尔标记: bool tag; (最后一次操作：0 为出队，1 为入队)
- 当 front == rear 时:
  - 若 tag == 0，说明刚发生过出队，此时为【队空】；
  - 若 tag == 1，说明刚发生过入队，此时为【队满】。
```

## 3.4 双栈模拟队列与均摊 O(1) 势能证明

如何用两个后进先出的栈（`stackIn` 与 `stackOut`）拼装出一个先进先出的队列？

```text
入队元素: 1, 2, 3
[ stackIn ]  ──(倒入)──>  [ stackOut ] ──> 出队
  │  3  │                   │  1  │
  │  2  │                   │  2  │
  │  1  │                   │  3  │
  └─────┘                   └─────┘
```

**操作法则**：
- **入队（push）**：直接压入 `stackIn`，时间复杂度 \(O(1)\)；
- **出队（pop/front）**：
  - 若 `stackOut` 不为空，直接从 `stackOut` 弹出；
  - 若 `stackOut` 为空，将 `stackIn` 的所有元素**一次性全部倒入** `stackOut`，再从 `stackOut` 弹出。

**均摊复杂度分析**：
每个元素在其生命周期内：
1. 压入 `stackIn` 一次（开销 1）；
2. 从 `stackIn` 弹出并压入 `stackOut` 一次（开销 2）；
3. 从 `stackOut` 弹出一次（开销 1）。  
任意元素最多被移动 4 次基本操作。连续 \(n\) 次操作的最坏总时间为 \(O(n)\)，**均摊单次操作时间严格为 \(O(1)\)**！

## 3.5 进阶利器：单调栈与单调队列实战模型

<a id="c03-3-5-1"></a>
### 3.5.1 单调栈（Monotonic Stack）：解决“下一个更大元素”

**定义**：栈内元素自底向上严格保持单调递增或递减。  
**应用场景**：在 \(O(n)\) 线性时间内找到每个元素左边/右边第一个比它大/小的元素。

```cpp
// 模板：寻找数组中每个元素右侧第一个比它大的元素（若无则返回 -1）
std::vector<int> nextGreaterElement(const std::vector<int>& nums) {
    int n = nums.size();
    std::vector<int> result(n, -1);
    std::stack<int> st; // 存储元素下标，栈内对应的值保持单调递减
    
    for (int i = 0; i < n; ++i) {
        while (!st.empty() && nums[i] > nums[st.top()]) {
            int prevIdx = st.top();
            st.pop();
            result[prevIdx] = nums[i]; // nums[i] 即为 nums[prevIdx] 右侧首个更大值
        }
        st.push(i);
    }
    return result;
}
```

<a id="c03-3-5-2"></a>
### 3.5.2 单调队列（Monotonic Queue）：滑动窗口最值问题

**问题**：大小为 \(k\) 的窗口在长度为 \(n\) 的数组上滑动，实时输出当前窗口内的最大值。若每次在窗口内遍历，复杂度为 \(O(nk)\)；利用**双端队列（`std::deque`）构建单调递减队列**，可优化至 \(O(n)\)。

**核心不变量**：
- 队列中仅保存可能成为未来窗口最大值的候选元素下标；
- 队列内元素值严格单调递减（队头永远是当前窗口最大值）；
- 新元素入队前，从队尾剔除所有小于等于它的元素（*“如果一个选手比你年轻还比你强，你就可以退役了”*）。

<a id="c03-summary"></a>
## 本章小结

1. **受限带来确定性**：栈与队列舍弃了随机访问的自由，换取了严格受控的 LIFO/FIFO 语义，是程序控制流与任务调度的心脏。
2. **循环取模化腐朽为神奇**：循环队列巧妙化解了假溢出，三种判空判满方案是计算机体系中缓冲区设计的经典范式。
3. **调度场算法的精髓**：用算符栈管理优先级，将人类习惯的括号嵌套结构扁平化为计算机直接线序吞吐的逆波兰式。
4. **单调性消除无效比较**：单调栈与单调队列通过及时剔除“不可能再成为最优解的冗余元素”，将高阶比较问题线性化降维至 \(O(n)\)。

## 思考题与经典面试题

1. **柱状图中最大的矩形**：给定 \(n\) 个非负整数表示柱状图中各个柱子的高度，每个柱子宽度为 1，求能在柱状图中勾勒出的矩形的最大面积。请使用单调栈给出 \(O(n)\) 解法并详细追踪状态。
2. **双端队列（Deque）的底层架构**：C++ 标准库中的 `std::deque` 既不是单纯的连续数组，也不是双向链表，而是采用“中央映射控制表 + 固定大小缓冲区（Block）”的分段连续架构。请分析这种设计在内存管理与下标随机访问上的权衡考量。
3. **单调队列的过期清除时机**：在滑动窗口最值问题中，如何准确判断并从单调队列头部剔除已经滑出窗口范围的过期元素？
