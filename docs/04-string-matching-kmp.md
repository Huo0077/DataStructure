# 第 4 章　字符串匹配（KMP）

> 难度：★★★☆☆ | 代码：[string_match.cpp](../string_match.cpp)

**前置知识**：[第 1 章](01-complexity-adt.md) 均摊分析（while 循环中 j 只减不增，减小次数 ≤ 增加次数，故均摊 O(1)），[第 2 章](02-linear-list.md) 线性表基本概念。

**学习目标**：理解暴力匹配的缺陷，掌握 KMP 前缀函数和 next 数组的含义，能手动计算 next 数组并追踪匹配过程。

<a id="c04-4-1"></a>
## 4.1 问题描述

给定**文本串 T**（长度 n）和**模式串 P**（长度 m），找出 P 在 T 中所有出现的位置。

<a id="c04-4-2"></a>
## 4.2 暴力匹配 → O(n·m)

```
for i = 0 to n-m:
    for j = 0 to m-1:
        if T[i+j] != P[j]: break
    if j == m: 匹配成功

最坏: T = "AAAAAAAAAB", P = "AAAAB" → O(n·m)
```

**最坏情况可视化**（每次匹配到最后一个字符才失败）：
```
T = "AAAAAAAAB", P = "AAB"
i=0: A A A|B → 比较了 3 次才失败
i=1:   A A B| → 比较了 3 次，其中前 2 次是重复劳动
...
总比较次数 ≈ (8-3+1) × 3 = 18，而 n=8, m=3, n×m=24 → 接近 O(n·m)
```

每次失配时 T 回退到 i+1 重头开始——已经比较过的字符信息被完全丢弃。

<a id="c04-4-3"></a>
## 4.3 KMP 的核心洞察

失配时**模式串已经匹配了 j 个字符** → 我们知道 T[i..i+j-1] = P[0..j-1]。

关键问题：**P[0..j-1] 的最长相等前后缀长度是多少？**

如果这个长度是 k，那么 P 的前 k 个字符和 T 的后 k 个字符已经自动对齐，**j 直接跳到 k 继续比较，T 无需回退**。

> 一句话总结：**利用已匹配部分的信息，将模式串"滑"到下一个可能匹配的位置。**

<a id="c04-4-4"></a>
## 4.4 前缀函数 π（next 数组）

**定义**：π[i] = P[0..i] 的**最长相等真前后缀**长度（真 = 长度 < i+1）。

```
P = "ABABCABAB"  逐位计算 π：

i=0: "A"        → 无真前后缀 → π[0]=0
i=1: "AB"       → "A"≠"B"    → π[1]=0
i=2: "ABA"      → "A"=="A"   → π[2]=1
i=3: "ABAB"     → "AB"=="AB" → π[3]=2
i=4: "ABABC"    → 无         → π[4]=0
i=5: "ABABCA"   → "A"=="A"   → π[5]=1
i=6: "ABABCAB"  → "AB"=="AB" → π[6]=2
i=7: "ABABCABA" → "ABA"=="ABA"→π[7]=3
i=8: "ABABCABAB"→"ABAB"=="ABAB"→π[8]=4

π = [0, 0, 1, 2, 0, 1, 2, 3, 4]
```

<a id="c04-4-5"></a>
## 4.5 计算前缀函数 O(m)

```
computePrefix(P):
    π[0] = 0
    j = 0                    // j = 当前匹配的前缀长度
    for i = 1 to m-1:
        while j > 0 and P[i] != P[j]:
            j = π[j-1]       // 退回较短的可能匹配长度
        if P[i] == P[j]:
            j++              // 匹配扩展
        π[i] = j             // 记录最长前后缀长度
```

**循环不变式**：在每轮 for 循环开始时，`j = P[0..i-1] 的最长相等前后缀长度`。

**while 为什么是均摊 O(1)？** j 每次最多 +1（for 循环每轮），减少的总次数不可能超过增加的总次数。所以 m 轮总操作 ≤ 2m → 均摊每轮 O(1)。

<a id="c04-4-6"></a>
## 4.6 KMP 匹配 O(n)

```
KMP(T, P):
    j = 0
    for i = 0 to n-1:
        while j > 0 and T[i] != P[j]:
            j = π[j-1]       // T 不后退！只调整 P 的指针
        if T[i] == P[j]:
            j++
        if j == m:
            匹配成功！位置 = i - m + 1
            j = π[j-1]       // 继续找下一个匹配
```

<a id="c04-4-7"></a>
## 4.7 KMP 匹配完整追踪

```
T = "ABABDABACDABABCABAB"  (n=19)
P = "ABABCABAB"            (m=9)
π = [0, 0, 1, 2, 0, 1, 2, 3, 4]

i=0..3: T[0..3]="ABAB", P[0..3]="ABAB" → j=4
i=4: T[4]=D, P[4]=C → 失配!
  j=π[3]=2 → P 跳到位置 2
i=4: T[4]=D, P[2]=A → 失配!
  j=π[1]=0 → P 跳到位置 0
i=4: T[4]=D, P[0]=A → 失配! → i++

i=5..9: 逐步匹配 → j=3
i=10: T[10]=C, P[3]=B → 失配! j=π[2]=1
i=10: T[10]=C, P[1]=B → 失配! j=π[0]=0
...

i=10..18: 重新匹配，最终 j=9=m → 匹配成功！位置 = 18-9+1 = 10 ✓

★ 注意 T 的指针 i 自始至终只前进，从不回退！
```

<a id="c04-4-8"></a>
## 4.8 第二个追踪实例（展示多次跳转）

```
P = "AAACAAA", n = 7
π = [0, 1, 2, 0, 1, 2, 3]

T = "AAACAAAAAC"
匹配:
i=0..2: T="AAA", P="AAA" → j=3
i=3: T[3]=C, P[3]=A → 失配! j=π[2]=2
i=3: T[3]=C, P[2]=A → 失配! j=π[1]=1
i=3: T[3]=C, P[1]=A → 失配! j=π[0]=0  ← 连续回退三次
i=3: T[3]=C, P[0]=A → 失配!
i=4..7: "AAAA" 逐步匹配 → j=4（但 P 只有 7 个字符）
...
最终匹配成功 @ i=3..9 "CAAAAAC"

★ 此例展示 while 循环可以连续回退多次——但总的回退次数不超前进次数
```

<a id="c04-4-9"></a>
## 4.9 nextval 优化

当 `P[j] == P[π[j]]` 时，回退到 π[j] 仍会失配（字符相同），可直接跳更远：

```
nextval[j] = (P[j] == P[π[j]]) ? nextval[π[j]] : π[j]
```

<a id="c04-4-10"></a>
## 4.10 延伸：KMP 与其他单模式匹配算法

- **Boyer-Moore**：从右向左匹配，坏字符+好后缀规则，实践中最快，O(n/m) 最好情况
- **Sunday**：比 BM 更简洁，检查 T 中模式窗之后的下一个字符
- **KMP**：被选入教材的原因——概念最清晰，保证 O(n+m)，且前缀函数的思想推广到了 AC 自动机和后缀数组

<a id="c04-summary"></a>
## 本章小结
- KMP 的核心贡献不是算法本身，而是一个思想：**"部分匹配的信息可以被结构化地编码和复用"**
- 前缀函数 π 将这种信息编码为数组，使匹配问题从"回溯搜索"变为"DFA 式的状态转移"
- O(m) 的前缀计算使用同样的思想递归地应用在模式本身上（模式匹配自己），使得算法设计高度自洽
- 均摊分析在 KMP 中有两处应用：前缀计算的 while 循环，和匹配阶段的 while 循环——j 的增加次数是其减少次数的上界
