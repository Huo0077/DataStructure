<a id="c10-10-1"></a>
## 10.1 多维空间索引的挑战：为什么 1 维 BST 失效？

在传统的业务场景中，我们检索的键通常是一维标量（如 `user_id = 10086`，或 `age BETWEEN 20 AND 30`）。BST 依赖一维数轴上的全序关系（Total Order）：对任意两个数 \(a\) 和 \(b\)，必定有 \(a < b\) 或 \(a > b\) 或 \(a = b\)。

然而，现实世界充满了**多维空间数据**：
- **地理信息系统（GIS）**：查找经纬度 \((x, y)\) 范围内距离当前位置最近的 5 家加油站；
- **游戏物理引擎**：三维空间 \((x, y, z)\) 中判定角色与障碍物的碰撞检测；
- **机器学习 / 推荐系统**：在 128 维人脸特征向量中查找与目标人脸欧氏距离最近的 Top-K 候选者。

### 为什么不能简单建立多个 1 维 BST？
若对 \(x\) 坐标建立 BST_x，对 \(y\) 坐标建立 BST_y：
- 在矩形范围 \([x_1, x_2] \times [y_1, y_2]\) 搜索时，BST_x 只能过滤 \(x\) 维，返回所有满足 \(x\) 范围的点，然后再逐个检验 \(y\)；
- 若点集在一条对角线上，BST_x 返回的点可能多达 \(O(n)\)，导致索引完全失效！

**我们需要一种能够“同时在多个维度上交替切割空间”的全新数据结构——KD 树（k-Dimensional Tree）！**

<a id="c10-10-2"></a>
## 10.2 KD 树的几何本质：正交超平面的空间剖分

1975 年，Jon Bentley 发明了 KD 树。其核心思想是：
- 它是对标准 BST 的高维推广；
- 树的每一个节点不仅存储一个 \(k\) 维坐标点，还隐式对应着**一个正交于某个坐标轴的超平面（Hyperplane）**；
- 该超平面将当前空间区域**一分为二**：处于该超平面“左侧”的点归入左子树，处于“右侧”的点归入右子树。

```text
2D 平面剖分示意图 (k = 2):
       y ^
         │                 │   (2, 7)
         │       (6, 12)   │
         │                 │         (17, 15)
         │─────────────────┼──────────────  y = 15 分割线
         │                 │ (9, 1)  (13, 15)
         │       (3, 6)    │
         │                 │
         └─────────────────┴───────────────────> x
                           x = 9 分割线
```

- **树根（第 0 层）**：选择 \(x\) 轴，用垂直于 \(x\) 轴的直线 \(x = 9\) 将平面划分为左右半区；
- **第 1 层节点**：选择 \(y\) 轴，在左右半区分别用水平直线 \(y = \dots\) 将空间再次横向剖分；
- **几何含义**：随着深度增加，整个多维空间被逐级细分为相互嵌套、互不重叠的**轴对齐超矩形包围盒（Axis-Aligned Bounding Box, AABB）**！

<a id="c10-10-3"></a>
## 10.3 KD 树的构建算法与维度切分策略

<a id="c10-10-3-1"></a>
### 10.3.1 轮换切分 vs 最大方差优先切分

1. **经典策略：维度周期轮换（Round-Robin）**  
   深度为 \(d\) 的节点，其分割维度直接定义为：
   \[
   \text{split\_dim} = d \bmod k
   \]
   在 2D 空间中：第 0 层切 \(x\)，第 1 层切 \(y\)，第 2 层切 \(x\)，第 3 层切 \(y\)，循环往复。
2. **进阶策略：最大方差优先（Maximum Spread / Variance）**  
   计算当前候选点集在各个维度上的坐标方差。**优先选择数据离散程度最大（方差最大）的维度进行切分**。这种策略能有效避免因为某个维度数据扎堆而导致的细长畸形空间剖分。

<a id="c10-10-3-2"></a>
### 10.3.2 中位数选取与 std::nth_element 线性建树优化（O(n log n)）

为了让 KD 树尽可能平衡（深度为 \(O(\log n)\)），**分割点必须选取当前维度坐标的中位数（Median）**。

- 若使用快速排序对点集全排序，建树时间为 \(O(k \cdot n \log^2 n)\)；
- **现代 C++ 优化**：使用 `std::nth_element`！它基于快速选择算法（QuickSelect），仅需 **\(O(n)\) 线性时间** 即可将中位数放置在正中间，并将较小者置于左侧、较大者置于右侧（无需完全有序）。
- **建树总时间复杂度**：根据主定理 \(T(n) = 2T(n/2) + O(n) \implies O(n \log n)\)！

```cpp
struct Point {
    std::vector<double> coords;
};

struct KDNode {
    Point point;
    int axis; // 本节点切分的维度
    KDNode *left, *right;
    KDNode(Point p, int a) : point(p), axis(a), left(nullptr), right(nullptr) {}
};

KDNode* buildKDTree(std::vector<Point>& points, int depth, int k) {
    if (points.empty()) return nullptr;
    
    int axis = depth % k;
    int mid = points.size() / 2;
    
    // O(n) 线性选择中位数
    std::nth_element(points.begin(), points.begin() + mid, points.end(),
        [axis](const Point& a, const Point& b) {
            return a.coords[axis] < b.coords[axis];
        });
        
    KDNode* node = new KDNode(points[mid], axis);
    
    std::vector<Point> leftPoints(points.begin(), points.begin() + mid);
    std::vector<Point> rightPoints(points.begin() + mid + 1, points.end());
    
    node->left = buildKDTree(leftPoints, depth + 1, k);
    node->right = buildKDTree(rightPoints, depth + 1, k);
    
    return node;
}
```

## 10.4 核心算法一：范围查询（Range Query）与包围盒相交剪枝

**问题**：给定一个超矩形范围（如 \([x_{\min}, x_{\max}] \times [y_{\min}, y_{\max}]\)，求落在其中的所有点。

```text
递归搜索规则:
1. 若当前节点所在点落在目标矩形内，加入结果集;
2. 检查左子树代表的包围盒是否与目标矩形相交:
   若相交，递归搜索左子树; 否则整棵左子树直接【剪枝】跳过!
3. 检查右子树代表的包围盒是否与目标矩形相交:
   若相交，递归搜索右子树; 否则整棵右子树直接【剪枝】跳过!
```

## 10.5 核心算法二：最近邻搜索（NNS）与 KNN 检索

**最近邻搜索（Nearest Neighbor Search, NNS）** 是 KD 树最惊艳的应用：给定查询点 \(Q\)，在集合中找出欧几里得距离最近的点。

<a id="c10-10-5-1"></a>
### 10.5.1 超球与超矩形相交判定的几何原理

设当前找到的全局最短距离为 \(R\)（即当前以 \(Q\) 为球心、半径为 \(R\) 的搜索超球内暂未发现更近的点）。

```text
                           超平面 x = P[axis]
                                 │
           [当前搜索侧]          │          [另一侧候选区域]
                                 │
                 Q (查询点)      │
               /   \             │
              /  R  \            │
             (   ●   )           │
              \     /            │
               \   /             │
                 v               │
            超球并未跨过分割线! ────┼───> 另一侧彻底剪枝! 无需探索!
                                 │
                                 │
                                 │
```

<a id="c10-10-5-2"></a>
### 10.5.2 剪枝不变量：垂直距离即为全局下界

**定理**：  
**查询点 \(Q\) 到分割超平面的垂直距离（即一维坐标差绝对值 \(|Q[\text{axis}] - P[\text{axis}]|\)），是 \(Q\) 到超平面另一侧区域内任何点的距离的严格数学下界！**
\[
\text{Distance}(Q, \text{AnyPointInOtherSide}) \ge |Q[\text{axis}] - P[\text{axis}]|
\]
**剪枝决策**：
- 若 \(|Q[\text{axis}] - P[\text{axis}]| \ge R\)：说明即使走到分割线边缘，距离都至少是垂直距离，已经大于等于当前最优解 \(R\)！因此**另一侧的子树中绝对不可能存在更近的点，整棵子树立即剪掉！**
- 仅当 \(|Q[\text{axis}] - P[\text{axis}]| < R\) 时，超球才“跨越”了分割线，必须进入另一侧子树递归搜寻。

<a id="c10-10-5-3"></a>
### 10.5.3 优先队列维护 K 近邻状态机
在求前 \(K\) 个最近邻（KNN）时，只需维护一个**大小为 \(K\) 的大顶堆**（存放当前找到的最近 \(K\) 个点）：
- 堆顶即为当前 Top-K 中的“最远距离”（门槛值 \(R\)）；
- 剪枝判断的标准就是看垂直距离是否小于堆顶距离；
- 一旦找到更近的点，淘汰堆顶，压入新点并下沉！

<a id="c10-10-6"></a>
## 10.6 维度灾难（Curse of Dimensionality）与工业界高维检索演进

KD 树在低维空间（\(k \le 10\)）表现极其优异，平均时间复杂度为 \(O(\log n)\)。然而在现代 AI 应用中，特征维度往往高达 128、512 甚至 1536 维。

### 为什么高维下 KD 树会退化？
- 在 \(k\) 维超空间中，一个超立方体有 \(2^k\) 个“角落”；
- 随着维度 \(k\) 的增大，**高维超球的体积占外接超立方体体积的比例指数级趋近于 0**！
- 几何效应导致：查询超球几乎必然与几乎所有的分割超平面相交，剪枝条件彻底失效，算法退化为全树遍历的 \(O(n)\)！

### 工业界高维近似最近邻（ANN）演进：
1. **球树（Ball Tree）**：以超球而非超矩形分割空间，对高维流形分布更具鲁棒性；
2. **局部敏感哈希（LSH）**：通过哈希函数将高维相近点映射到同一桶；
3. **基于图的近邻索引（HNSW / Hierarchical Navigable Small World）**：**当前所有主流向量数据库（Milvus、Pinecone、Faiss）的核心引擎**，以可导航小世界图网络在毫秒级内实现高维向量检索。

<a id="c10-summary"></a>
## 本章小结

1. **正交剖分是多维索引的基石**：KD 树将 1 维二分查找升维为多维空间的正交超平面切分。
2. **中位数保障树高平衡**：借助 `std::nth_element`，以 \(O(n \log n)\) 线性对数时间完成整树构建。
3. **垂直距离下界是剪枝灵魂**：超球与超平面的几何距离比对，赋予了 NNS 与 KNN 惊人的分支剪枝能力。
4. **理性认识维度灾难**：KD 树是低维空间检索（GIS、游戏物理引擎）的神器，而高维 AI 向量检索应积极拥抱 HNSW 与图索引。

## 思考题与经典大厂面试题

1. **2D 范围查询的时间复杂度界限**：在包含 \(n\) 个点的 2D KD 树中，证明任意正交矩形范围查询的最坏时间复杂度为 \(O(\sqrt{n} + k)\)，其中 \(k\) 为返回的结果点数。
2. **点插入与删除导致的失衡**：如果在构建好的 KD 树上频繁执行动态插入和删除，树形结构可能会严重倾斜。工业界通常如何借鉴替罪羊树（Scapegoat）思想对 KD 树进行局部重平衡？
3. **KNN 搜索中进入分支的先后顺序**：在最近邻搜索中，应当先进入包含查询点 \(Q\) 的同侧子树，还是先进入异侧子树？为什么这一顺序对于提升剪枝效率至关重要？
