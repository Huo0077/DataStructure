## 2.1 线性表的本质与存储哲学：顺序 vs 链式

线性表（Linear List）是最基础、最直观的逻辑结构：存在唯一的首元素和尾元素，除首尾外，每个元素有且仅有一个直接前驱（Predecessor）和一个直接后继（Successor）。

然而，同一逻辑结构在物理内存中有两种截然相反的实现哲学：

```text
【顺序表 (Sequential List)】
内存布局: 紧密相连的一整块连续物理地址
┌─────────┬─────────┬─────────┬─────────┬─────────┐
│ data[0] │ data[1] │ data[2] │ data[3] │   ...   │
└─────────┴─────────┴─────────┴─────────┴─────────┘
寻址公式: Loc(i) = BaseAddress + i * sizeof(ElemType)  ───> O(1) 随机访问

【链表 (Linked List)】
内存布局: 散落在内存堆各处的独立节点，通过指针串联
┌────────┬────┐      ┌────────┬────┐      ┌────────┬──────┐
│ data=10│next┼────> │ data=20│next┼────> │ data=30│nullptr│
└────────┴────┘      └────────┴────┘      └────────┴──────┘
寻址方式: 必须从 head 开始沿 next 指针逐个跳跃 ───────────> O(n) 顺序访问
```

<a id="c02-2-1-1"></a>
### 2.1.1 顺序表（数组实现）与容量扩充策略

顺序表的核心结构包含三个要素：
```cpp
template <typename T>
class SeqList {
    T* data;          // 指向堆内存中连续数组的指针
    size_t length;    // 当前实际存储的元素个数（逻辑长度）
    size_t capacity;  // 当前分配的物理内存容量（物理容量）
};
```

**为什么扩容因子（Growth Factor）通常选 1.5 或 2？**
- 若每次仅增加固定大小（如每次 +10），插入 \(n\) 个元素将触发 \(O(n)\) 次内存重分配与数据搬移，总代价退化为 \(O(n^2)\)，均摊单次插入为 \(O(n)\)。
- 若采用**几何级数扩容（如 2 倍）**，根据第 1 章的均摊分析，均摊插入代价为 \(O(1)\)。
- **工程细节**：MSVC STL 采用 1.5 倍扩容，GCC libstdc++ 采用 2 倍扩容。1.5 倍的优势在于允许之前释放的内存块在后续扩容中被重新复用，减少内存碎片。

<a id="c02-2-1-2"></a>
### 2.1.2 现代硬件视角：CPU 缓存局部性（Cache Locality）的决定性影响

在 1980 年代，内存速度与 CPU 主频相当，链表因其“插入删除不搬移数据”而广受推崇。但今天，**CPU 访问寄存器/L1 Cache（~1ns）与访问主存（~50-100ns）存在百倍延迟鸿沟**！

- **顺序表**：物理空间连续，CPU 抓取一个元素时，硬件预取器（Prefetcher）会自动将相邻整行（Cache Line，通常 64 字节）载入高速缓存，**空间局部性极高**。
- **链表**：节点由 `new` 动态分配，内存地址随机分布在堆中，每次访问 `curr->next` 极易引发 **Cache Miss（缓存未命中）**，导致流水线停顿等待内存读取。

> **工业界实战铁律**：  
> 除非有极其高频的已知位置插入/删除且绝对无法承受搬移开销，否则在大多数现代业务场景中，**优先选用 `std::vector` 而非 `std::list`**。即使是中途插入删除，在元素尺寸较小时，`std::vector` 的内存搬移速度往往依然快于链表指针寻址的开销！

## 2.2 单向链表（Singly Linked List）与操作手算演练

<a id="c02-2-2-1"></a>
### 2.2.1 节点定义与核心操作复杂度

```cpp
struct ListNode {
    int data;
    ListNode* next;
    ListNode(int val) : data(val), next(nullptr) {}
};
```

| 操作 | 时间复杂度 | 关键注意点 |
| :--- | :---: | :--- |
| **头部插入** | \(O(1)\) | `newNode->next = head; head = newNode;` 顺序不可颠倒 |
| **尾部插入** | \(O(n)\) | 需遍历至尾节点；若维护了 `tail` 指针则优化为 \(O(1)\) |
| **按值查找** | \(O(n)\) | 顺序比对，无法二分（不支持随机下标寻址） |
| **删除给定节点** | \(O(n)\) | 单链表需从头遍历找到其**直接前驱节点**才能断开链接 |

<a id="c02-2-2-2"></a>
### 2.2.2 经典三指针原地反转算法详解（Dry-Run 演练）

反转链表是所有数据结构面试的试金石。最优雅且空间为 \(O(1)\) 的方法是**迭代三指针法**：`prev`、`curr`、`next`。

**算法核心不变量**：
- `prev` 始终指向已经成功反转好的链表新头；
- `curr` 是当前正准备反转指向的节点；
- `next` 用于暂存 `curr` 原有的后继，防止断链后“丢失后续世界”。

```cpp
ListNode* reverseList(ListNode* head) {
    ListNode* prev = nullptr;
    ListNode* curr = head;
    while (curr != nullptr) {
        ListNode* next = curr->next; // 1. 暂存后继
        curr->next = prev;           // 2. 翻转当前节点的指针
        prev = curr;                 // 3. prev 前进
        curr = next;                 // 4. curr 前进
    }
    return prev; // prev 成为新头
}
```

#### 分步跟踪演练（Dry-Run Trace）
假设输入链表为：`1 -> 2 -> 3 -> nullptr`

```text
【初始状态】
  prev = nullptr, curr = [1]
  [1] ───> [2] ───> [3] ───> nullptr

【第 1 轮循环】
  1. next 暂存 [2]
  2. curr->next = prev  ==>  [1] ───> nullptr
  3. prev = curr        ==>  prev = [1]
  4. curr = next        ==>  curr = [2]
  状态: nullptr <── [1] (prev)    [2] (curr) ───> [3] ───> nullptr

【第 2 轮循环】
  1. next 暂存 [3]
  2. curr->next = prev  ==>  [2] ───> [1]
  3. prev = curr        ==>  prev = [2]
  4. curr = next        ==>  curr = [3]
  状态: nullptr <── [1] <── [2] (prev)    [3] (curr) ───> nullptr

【第 3 轮循环】
  1. next 暂存 nullptr
  2. curr->next = prev  ==>  [3] ───> [2]
  3. prev = curr        ==>  prev = [3]
  4. curr = next        ==>  curr = nullptr (循环终止)
  状态: nullptr <── [1] <── [2] <── [3] (prev)

【最终返回】
  返回 prev ([3])，反转彻底完成！
```

## 2.3 双向链表（Doubly Linked List）与空间换时间

在单链表中，如果要删除一个节点 `p`，必须知道它的前驱。若只持有 `p` 本身的指针，必须花费 \(O(n)\) 从头遍历。  
双向链表通过每个节点增加一个 `prev` 指针，实现了前驱与后继的对称访问。

```text
nullptr <─── [prev|10|next] <═══> [prev|20|next] <═══> [prev|30|next] ───> nullptr
```

### \(O(1)\) 删除指定节点：
```cpp
void removeNode(DNode* node) {
    if (!node) return;
    if (node->prev) node->prev->next = node->next;
    if (node->next) node->next->prev = node->prev;
    delete node;
}
```
> **代价**：每个节点多耗费一个指针空间（在 64 位系统上增加 8 字节开销），典型的**以空间换时间**策略。广泛应用于操作系统的双向循环任务队列、LRU 缓存机制等。

## 2.4 循环链表与约瑟夫环（Josephus Problem）数学推导

循环链表（Circular Linked List）的尾节点不指向 `nullptr`，而是重新指向 `head`。

**经典案例：约瑟夫问题（Josephus Problem）**  
\(n\) 个人围成一圈（编号 0 到 \(n-1\)），从第 0 个人开始报数，数到第 \(m\) 的人出局，下一个人重新从 1 报数，求最后幸存者的编号。

```text
          0 ───> 1
        ^         \
       /           v
      4 <── 3 <─── 2
```

1. **模拟法（循环链表）**：时间复杂度 \(O(n \cdot m)\)，空间复杂度 \(O(n)\)。
2. **数学递推法（严格推导）**：  
   设 \(J(n, m)\) 为 \(n\) 个人报数到 \(m\) 出局的最终胜出者编号。
   - 第一轮出局的人编号为 \((m - 1) \bmod n\)；
   - 剩下 \(n - 1\) 个人从第 \(m \bmod n\) 个人开始重新形成新一轮编号；
   - 新旧编号存在严格的映射位移关系：
   \[
   J(n, m) = (J(n - 1, m) + m) \bmod n
   \]
   基础条件：\(J(1, m) = 0\)。  
   由此，可在 \(O(n)\) 时间、\(O(1)\) 辅助空间内直接算得幸存者！

## 2.5 链表四大工程杀手锏

<a id="c02-2-5-1"></a>
### 2.5.1 哨兵节点（Dummy Node）：彻底消灭头尾特判

在操作链表时，最容易出现的 Bug 就是对“空链表”或“在头部插入/删除”进行繁琐的 `if (head == nullptr)` 特判。  
**哨兵节点技巧**：在堆上或栈上分配一个虚拟头节点 `dummy`，令 `dummy.next = head`。此时，真正的头节点也有了统一的直接前驱 `dummy`！

```cpp
// 示例：删除链表中所有值为 val 的节点（若无哨兵，头节点恰为 val 时处理极易出错）
ListNode* removeElements(ListNode* head, int val) {
    ListNode dummy(0);
    dummy.next = head;
    ListNode* curr = &dummy;
    
    while (curr->next != nullptr) {
        if (curr->next->data == val) {
            ListNode* del = curr->next;
            curr->next = del->next;
            delete del;
        } else {
            curr = curr->next;
        }
    }
    return dummy.next;
}
```

<a id="c02-2-5-2"></a>
### 2.5.2 快慢指针（Floyd 判环与环入口严格数学证明）

**算法流程**：
- 定义快慢两指针：`slow` 每次走 1 步，`fast` 每次走 2 步；
- 若链表无环，`fast` 必先到达 `nullptr`；
- 若链表有环，`fast` 与 `slow` 必然在环内相遇。

```text
          头节点
            │
            ▼   a 步           环入口
            o ───> o ───> ... ───> ● ───> o ───> ... ───> ★ 相遇点
                                   ^                      │
                                   │       b 步           │
                                   └──────────────────────┘
                                           L - b 步
```

#### 环入口定位的严格代数推导：
- 设链表头到环入口的距离为 \(a\)；
- 设环入口顺时针到相遇点的距离为 \(b\)；
- 设环的总周长为 \(L\)。
- 当两指针在 ★ 相遇时：
  - `slow` 走过的路程：\(S = a + b\)；
  - `fast` 走过的路程：\(F = a + b + k \cdot L\)（\(k \ge 1\)，表示快指针在环内多转了 \(k\) 圈）；
- 因为 `fast` 的速度是 `slow` 的 2 倍，故路程关系满足：
  \[
  F = 2S \implies a + b + k \cdot L = 2(a + b) \implies a = k \cdot L - b = (k - 1)L + (L - b)
  \]
- **物理含义**：  
  从链表头走 \(a\) 步到达环入口的距离，**恰好等于** 从相遇点沿环继续走 \((L - b)\) 步再加上若干整圈的距离！
- **操作结论**：  
  两指针相遇后，将 `slow` 重新指向链表头，`fast` 停留在相遇点；此后两者均每次走 1 步。当它们再次相遇时，**所处位置必定是环的入口节点**！

<a id="c02-2-5-3"></a>
### 2.5.3 寻找链表中点与归并排序应用
- `slow` 每次走 1 步，`fast` 每次走 2 步；
- 当 `fast->next == nullptr`（奇数长度）或 `fast->next->next == nullptr`（偶数长度）时，`slow` 恰好停留在中点。
- 这是在 \(O(n \log n)\) 时间内对单链表进行**归并排序（Merge Sort）**的关键子过程。

<a id="c02-summary"></a>
## 本章小结

1. **结构决定行为**：顺序表长于随机检索（\(O(1)\)），劣于动态插入；链表长于已知位置的增删（\(O(1)\)），劣于查找（\(O(n)\)）。
2. **硬件改变世界**：现代 CPU 缓存机制让顺序表（`std::vector`）在绝大多数普通应用场景下综合性能大幅胜过链表。
3. **指针操作的黄金守则**：改链之前，**先存后继**，再接新链；释放内存防止野指针与内存泄漏。
4. **哨兵与双指针**：哨兵节点解决的是**代码边界的繁琐特判**；快慢双指针解决的是**无额外空间下的拓扑特征探测（环、中点、倒数第 k）**。

## 思考题与经典面试题

1. **K 个一组翻转链表**：给定一个单链表，每 \(k\) 个节点一组进行翻转，如果最后剩余节点不足 \(k\) 个则保持原样。请使用迭代法实现，并分析其时间与空间复杂度。
2. **双指针相遇圈数证明**：在 Floyd 判环算法中，证明当 `slow` 进入环后，在它走完第一圈（\(\le L\) 步）之内，`fast` 必定会追上它。
3. **O(1) 时间删除无前驱节点**：如果只给你一个指向链表中间某个节点 `p` 的指针（非尾节点），且不知道头节点指针，如何以 \(O(1)\) 时间复杂度“删除”该节点？这种技巧有什么潜在隐患？
