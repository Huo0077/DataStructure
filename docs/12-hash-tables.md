# 第 12 章　哈希表

> 难度：★★☆☆☆ | 代码：[hashing.cpp](https://github.com/Huo0077/DataStructure/blob/main/hashing.cpp)

**前置知识**：[第 1 章](01-complexity-adt.md) 均摊分析（重哈希的均摊 O(1)），[第 2 章](02-linear-list.md) 链表（分离链接法用链表）。

**学习目标**：理解哈希函数的映射思想，掌握冲突处理的三种方式及其优劣。

**核心思想**：通过哈希函数 `h(key)` 将键直接映射为数组下标 → O(1) 平均查找。

<a id="c12-12-1"></a>
## 12.1 冲突处理

<a id="c12-topic-01"></a>
### 拉链法 (Separate Chaining)

每个槽位存一个链表。冲突就追加。删除直接操作链表。

```
槽0: [k1,v] → [k3,v]     α = n/m（负载因子）
槽1: [k2,v]               α 越大 → 链表越长 → 性能越差
槽2: (空)
槽3: [k4,v] → [k5,v]
```

<a id="c12-topic-02"></a>
### 开放地址法 (Open Addressing)

冲突时在表中找下一个空槽。删除需**惰性删除**（标墓碑），否则查找链断裂。

| 方法 | 探测序列 | 问题 |
|------|------|------|
| 线性探测 | h+0, h+1, h+2... | **一次聚集**——连续占用拉长探测 |
| 平方探测 | h+0², h+1², h+2²... | 二次聚集，表大小需素数 + α<0.5 |
| 双重哈希 | h₁ + i·h₂ | 最佳，不同 key 不同探测路径 |

**负载因子与探测长度**（开放地址法）：

| α | 成功查找平均探测 | 不成功查找平均探测 |
|---|-----------------|-------------------|
| 0.5 | 1.5 | 2.5 |
| 0.75 | 2.5 | 8.5 |
| 0.9 | 5.5 | 50.5 |

> 表中可见 α > 0.75 后性能急剧恶化（"膝盖效应"）。这就是为什么哈希表通常在 α ≈ 0.75 时扩容。

**为什么表大小应取素数？**
```
反例: keys = 6, 12, 18, 24, 30（全是 6 的倍数）
  tableSize = 12: h(k)=k%12 ∈ {0,6} → 只用了 2 个槽！系统聚集
  tableSize = 13: h(k)=k%13 ∈ {6,12,5,11,4} → 5 个槽均匀散布 ✓
素数表大小让周期性规律失效——这就是数论的功劳。
```

**双重哈希约束**：`h₂(key)` 必须与 tableSize 互质。简单方案：取 tableSize 为素数，`h₂(key)` 返回 `[1, tableSize-1]` 范围内的值。

<a id="c12-topic-03"></a>
### 再哈希 (Rehashing)

α > 阈值（0.7~0.75）→ 扩容 + 全量重插。单次 O(n)，均摊 O(1)。

<a id="c12-12-2"></a>
## 12.2 完美哈希 (FKS)

> 代码 [hashing.cpp](https://github.com/Huo0077/DataStructure/blob/main/hashing.cpp) 中的 `PerfectHash` 类实现了 FKS 双层完美哈希。

**思想**：第一层哈希分桶，第二层给每个桶一个无冲突的哈希表（表大小 = 桶大小的平方）。如果任何第二层桶还有冲突，换一个新的哈希函数重建。期望总空间 O(n)，查询严格 O(1)。

```
第一层: h1(key) → 桶 b
第二层: h2_b(key) → 桶 b 内的唯一位置

查询一定 O(1)——因为第二层保证无冲突！
代价：构建期望 O(n)，但最坏可能需要多次重建。
```

<a id="c12-12-3"></a>
## 12.3 哈希函数设计

**整数**：`h(k) = k % tableSize`，tableSize 建议素数（减少规律性冲突）。

**字符串**（多项式哈希 / Horner 法）：
```cpp
unsigned hash(const string& s) {
    unsigned h = 0;
    for (char c : s) h = h * 31 + c;  // 31=素数, h*31=(h<<5)-h
    return h % tableSize;
}
```

<a id="c12-12-4"></a>
## 12.4 哈希表的局限性

- 无序（无法范围查询）
- 最坏 O(n)（哈希函数差或哈希碰撞攻击）
- 空间利用率低（需要预留空槽）
- 需要好的哈希函数设计

<a id="c12-summary"></a>
## 本章小结
- 哈希以概率换性能——期望 O(1) 的代价是放弃确定性（最坏 O(n)）和顺序性（无法范围查询）
- 哈希函数是灵魂——好的哈希让一切简单，坏的哈希让一切 O(n)
- 两种冲突处理家族各有侧重：拉链法灵活简单，开放地址法缓存友好（连续内存）
- 完美哈希通过双层策略消除了输入分布的依赖，实现严格 O(1) 查询——但构建代价较高
- 理解负载因子 α 是理解哈希表行为的关键——它决定了"满"的程度和性能曲线的转折点
